## Design

- Crate `forecast-config` at `src/core/config/`, standalone (no root manifest
  is in any task's scope; ADR-0001). `publish = false`; lints forbid
  `unsafe_code` and warn on `missing_docs`. No dependencies.
- `load(project_root, environment)` reads `configs/base.toml`, then
  `configs/environments/<environment>.toml`; the environment file replaces base
  values key by key. The caller must name the `Environment`; names are exact
  (`development`, `production`). A relative `project_root` is rejected, so
  loading never depends on the working directory. Loading never reads the
  process environment.
- Closed schema: `[paths]` `data`/`models`/`runtime` (required; resolved
  against the project root), `[logging]` `level` (required; `TRACE` … `CRITICAL`
  as in `LOGGING_OBSERVABILITY_RULES`), `[secrets]` (optional). Any other table
  or key is an error. No value has a default.
- Secrets: `[secrets]` values must be references `"env:VARIABLE"`. A reference
  is resolved only on request (`SecretRef::resolve`). `Secret` has a redacted
  `Debug` and no `Display`. Literal values in `[secrets]` are rejected.
- Errors: `ConfigError::{UnknownEnvironment, RelativeProjectRoot, Read, Syntax,
  Invalid}`; `Invalid` lists every problem with file and line where one exists.
  Messages name files, lines, tables and keys but never reproduce values, so a
  mistakenly pasted secret is not echoed.
- Reader: strict TOML subset — `[table]` headers, `key = "string"`,
  comments, LF/CRLF. Arrays, inline tables, numbers, booleans, dates, literal
  and multi-line strings, escapes, dotted and quoted keys, duplicates and
  control characters are rejected, so every accepted file is valid TOML with
  the same meaning.

## Known limitations

1. The reader supports only the TOML subset above. Replace it with a TOML crate
   once a dependency policy permits one (ADR-0001, follow-up 1).
2. The only secret source is the process environment. How variables are
   supplied (shell, systemd `EnvironmentFile`, a secret manager) is a
   deployment concern. Resolved values are not zeroized on drop (that would need
   `unsafe` or a dependency).
3. Paths are not checked for existence while loading; directory availability
   belongs to storage and system health.
4. No health component exists yet, so configuration state is not reported
   through system health. `ConfigError` and `SecretError` are typed so a later
   health/System view can expose them (`SYSTEM_HEALTH_CONTRACT`).
5. The schema is closed. A later task that needs new configuration needs
   `configs/` and `src/core/config/` in its allowed files; only MFA-0101 lists
   them (ADR-0001, follow-up 3).
6. The crate is standalone until a workspace layout is decided (ADR-0001,
   follow-up 2). Run its tests with
   `cargo test --manifest-path src/core/config/Cargo.toml`.
7. HawkScan (DAST) was not run: there is no running HTTP application and no
   `HAWK_API_KEY`.
